ClawTeam 是面向 AI Agent 团队的命令行编排框架——让 Claude Code、Codex、Gemini 等任意终端客户端，像一支真正的软件工程团队一样：分任务、共状态、可追溯、能交接。

任务状态消失

Prompt 上下文滚走，谁做了什么、为什么做，全部丢失。

工作冲突与重复

多 Agent 并行修改同一文件，无 Git 感知，合并时才发现冲突。

我们的方案

一个 CLI
协调所有 Agent

ClawTeam 提供 Agent 团队所需的全部协调原语，无需修改任何 Agent 本身。

01

共享任务图谱

一块看板，所有 Agent 可见；依赖链、优先级、所有权实时追踪。

02

持久化收件箱通信

文件驱动的消息队列，Prompt 滚动后交接依然完整可查。

03

Git Worktree 隔离

每个 Agent 在独立分支工作，冲突检测自动完成，最终可合并。

技术架构

三层协调原语

共享任务图谱

原子文件写入 + 依赖链锁定。
Agent 完成任务自动解锁下游阻塞，无需 Leader 手动干预。

clawteam task create · update · wait

持久化收件箱

每个 Agent 拥有独立的文件消息队列。
Prompt 滚动≠信息丢失；旁听模式（peek）让 Leader 实时掌握全局对话。

clawteam inbox send · receive · peek

Git Worktree 隔离

每个 Agent spawn 时自动创建独立 worktree。
并行修改互不干扰；context conflicts 命令在合并前自动检测冲突。

clawteam context conflicts · inject

多后端 Spawn

支持 tmux（可视终端）和 subprocess（无头）两种后端，同一 API 透明切换。
Profile 系统管理不同 AI 提供商的认证与模型配置。

clawteam spawn tmux|subprocess

生命周期管理

Idle 通知、graceful shutdown、快照与恢复——团队状态可在任意时间点存档并还原。

clawteam lifecycle · snapshot · restore

实时看板 + Discord

TUI 看板、Web Dashboard，以及 Discord 桥接——用户可以直接在聊天频道@任意 Agent 并收到回复。

clawteam board live · serve

核心差异化

为什么是 ClawTeam？

现有工具（LangGraph、AutoGen、CrewAI）都要求你重新包装 Agent；ClawTeam 不侵入任何 Agent——它是一个纯协调层，任何终端 CLI 开箱即用。
✅
框架无关
无需 SDK 嵌入，任何 CLI Agent 即插即用
✅
本地优先，无云依赖
文件系统驱动，数据不离开本机
✅
Git 原生

✅

一条命令启动预设角色完整团队

产品思维：协调 > 能力

顶层洞察：Agent 能力不是瓶颈，协调失败才是。ClawTeam 解决的是系统问题。

🏗️

工程思维：原子操作 + 文件系统

所有状态写入文件，原子 tmp+rename 防止竞争；无数据库，无中间件依赖。

🚀

开发者体验：pip install 即用

零配置启动，内置模板覆盖最常见场景，profile 系统处理高级定制。

🔒

安全内置：平安喵

高危命令必须经过 ping-an-miao 审查，安全不是事后补丁而是团队角色。

📊

可观测性：多维看板

TUI、Web Dashboard、Discord 桥接三种观测面，适配不同使用场景。
