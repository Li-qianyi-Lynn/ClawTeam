产品思维

😿

痛点

AI Agent（Claude Code / Codex / Gemini）各自为战，无法协同分工。
大任务串行处理，上下文频繁溢出，人工交接成本极高。

→
💡

洞察

Agent 协作本质是共享状态 + 原子操作，而非实时对话。
需要任务图、消息队列、冲突检测——像工程团队，不是聊天室。

→
🚀

方案

ClawTeam：统一调度 CLI + 共享任务板 + 跨 Agent Inbox + Git Worktree 隔离。
任何终端 AI Agent 插入即用，零代码改动。

3x 任务并行度提升
6+ 支持 AI 客户端
0 代码侵入
1 cmd 启动完整团队

技术架构

🤖 AI Agents Layer
Claude Code Codex Gemini Any CLI
↓  clawteam spawn tmux claude
⚙️ ClawTeam Core
Task Board Inbox Queue Lifecycle Context
↓  原子写入 / 消息消费
🏗️ Infrastructure
Git Worktrees File-based Queue tmux / subprocess

关键技术决策

  • 文件队列 vs 消息中间件 → 零依赖、支持离线、原子 tmp+rename 防竞态
    tmp→rename no-dep
  • Git Worktree 隔离 → 多 Agent 并行改代码不冲突，改动可追溯
    worktree context inject
  • Provider-agnostic 设计 → Profile + Preset 解耦 Agent 身份与运行时，一行切换厂商
    --profile preset generate
  • 任务依赖图自动解锁 → blocked-by 链完成后自动 pending，无需人工干预
    --blocked-by auto-unblock

项目展示

核心能力

  • 🗂️ 共享任务看板 — 阻塞关系、优先级、进度一目了然，支持 high / blocked 状态流转
  • 📬 Inbox 消息系统 — Agent 间异步通讯，幂等消费，不依赖实时连接
  • 🌿 Git Worktree 隔离 — 多 Agent 并行修改，自动 merge，冲突检测
  • 📊 Board 实时监控 — TUI 看板 + 浏览器端双模式，gource 可视化
  • 🔌 Provider 无关 — Profile 一行切换 Claude / Gemini / Kimi
  • 🛡️ 高危命令审批 — lifecycle 流程，平安喵点头才执行

总结 & Q&A

关键收获

  • 协议先行 — 多 Agent 协作要先约定接口契约， 接口不稳则返工率高；任务图比人工交接可靠 10 倍
  • 简单即鲁棒 — 文件系统 > 消息中间件； 原子写入解决 90% 并发问题，无需引入复杂依赖
  • 产品 = 能力映射 — 把 AI Agent 能力映射到人类团队心智模型， 降低用户认知门槛是最大的产品壁垒
